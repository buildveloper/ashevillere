# Product & Business
- Prefers monetization/business mechanics that are legally compliant; will remove a planned mechanic on legal grounds (e.g., NC law barring referral fees paid to unlicensed parties) and wants the rationale recorded in the spec. Confidence: 0.8
- Treats data honesty as the product's core differentiator: never simulate a "CHECKED"/complete state or show source citations without real data behind them — an honestly unfinished "not yet connected — live [date]" state is preferable to fake completion, because faking results is exactly what the product is positioned against. A card may only flip to "CHECKED" when the actual fetch succeeds and returns real data; unreachable or empty upstreams must render an honest error/unavailable state, never a silent fallback to fake data. Confidence: 0.95
- Once an honest data pattern is established for one card (e.g., the flood card: real fetch → CHECKED, honest UNAVAILABLE on failure, never fake data), later features must match that pattern exactly — the reference card is the template, not something to re-negotiate per feature. Confidence: 0.8
- Wants legal/statute citations to be exact — cite the precise subsections (e.g., NC G.S. 93A-2(a), G.S. 93A-6(a)(9)) and mirror the authoritative spec's wording verbatim; approximate references like "93A-6(b)" are treated as inexact bugs to fix. Confidence: 0.75
- Wants the agent to independently verify claimed ground truth (e.g., which flood zone a test address falls in) against an authoritative public source rather than trusting whatever the code returns — test addresses must be chosen to cover genuinely different cases and checked against an official/independent source. For features where ground truth varies by address, expects one test address independently verified as affected (damage/reported area) and one verified as unaffected, stating exactly how each was confirmed (news coverage, county records, GIS layer directly) — the same standard used for flood zones and jurisdiction. Confidence: 0.8
- Even in honest unavailable/error states, the UI must surface a working link to the official source of truth (e.g., the FEMA NFHL page) so users can verify directly — a bare placeholder like "SOURCE PENDING" with no link in an unavailable state is treated as a defect to fix, not acceptable UX. Confidence: 0.6
- Treats the honesty contract (CHECKED only on a real successful fetch, honest UNAVAILABLE on failure, never fabricated data) as invariant during scoped work — a performance/copy fix must not touch that logic ("this is a performance and copy fix, not a rebuild"). Confidence: 0.8
- Factual claims in product copy must be grounded in the project spec or a verified authoritative source — an unverified claim picked up from general web research (e.g., county STR "registration and occupancy taxes") must be softened to what's actually confirmed, and a real claim cited using the established citation pattern (like the flood panel cites FEMA/NC FRIS). On sensitive subject matter (real property loss, loss of life), tone must be factual and neutral only — no embellishment or dramatic language — and when a data source doesn't have something, say so plainly and stop rather than filling the gap with a plausible-sounding sentence from elsewhere: zero tolerance for unsourced specifics. Confidence: 0.9
- Prefers non-repetitive user-facing copy — a fact should be stated once, clearly (e.g., flagged the "confirm permit status with the City of Asheville" sentence appearing three times in one panel). Confidence: 0.7
- Extends the honesty contract to data-matching fallbacks: when an approximate/spatial fallback can't produce a trustworthy match (e.g., a nearest-parcel lookup that would silently return a *neighbor's* parcel for a street-centerline-geocoded point), remove it and return an honest unavailable rather than presenting the wrong property's data — checking the wrong parcel is worse than saying the parcel couldn't be matched. Negative results ("no record") must carry the caveat that absence is not a guarantee — the dataset only reflects what was reported to the county. Confidence: 0.8
- Every data panel must show its source citation with a last-updated date/status visible (e.g., the recovery panel cites "Buncombe Co. open data — Helene damage parcels" with lastUpdated "County-maintained"), matching the pattern set by the other panels — a source line without a last-updated indicator is incomplete. Confidence: 0.75
- The search flow must accept the bare street address users naturally type (e.g., "287 New Salem Rd" with no city/state) and resolve it to the parcel — a "NO MATCH" on that input is a bug to fix (via the county's own address data when the Census geocoder requires city context), not acceptable UX. Confidence: 0.65
